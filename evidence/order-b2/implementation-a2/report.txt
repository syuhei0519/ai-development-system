Design and adoption
Both dependency RUNs accept optional BuildKit secret id=build_ca, read-only and
required=false. If present, a nonempty file is selected using command-local
SSL_CERT_FILE, then go mod download performs normal TLS and checksum verification.
No secret mount is added to the later test/build RUN or runtime stage. The ordinary
CI path supplies no secret and retains standard trust. OCI_BUILD_CA_FILE is an
optional local build-helper input; no GitHub Secret/Environment/token is created
or required. The source file must stay outside the build context.

Rejected alternatives: COPY-and-delete can retain the CA in layers; persistent
ARG/ENV or truststore installation widens scope/lifetime; daemon-only CA does not
supply Dockerfile RUN trust. TLS disabling, GOINSECURE, module-source substitution
and new credentials are prohibited and absent. BuildKit secret mounts are the
standard temporary transport: https://docs.docker.com/build/building/secrets/ .

Risks and boundaries
A supplied CA changes who may authenticate dependency HTTPS during that RUN; only
an existing authorized bundle may be used. Standard certificate directories may
still authenticate ordinary public endpoints, so unrelated/invalid PEM does not
universally guarantee failure outside a custom-issuer environment. Secret contents
are not cache keys; cold isolated builds are required for trust-change verification.
