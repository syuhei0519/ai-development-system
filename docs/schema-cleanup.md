# 検証する形式を最新版に揃える

## 目的

同じ契約の複数版を現行ツリーに並べず、現在使える形式を明確にする。

## やったこと

Delivery 1.3、Issue Completion / Readiness 1.1 に揃え、Handoff 2.0 / Knowledge 1.0 は維持した。
旧 schema 14本を削除し、旧版入力は拒否する。CLI・テスト・架空の例・文書を合わせて更新した。
過去の実データや失敗を新版へ書き換えず、変更前の固定履歴で再現する。
大きな架空の統合例はテストの一時ディレクトリに生成し、保存済みの旧例は履歴索引に置換した。

## 観察結果

393テストと、現行の CLI 検証が成功した。
旧版・不正 JSON・改変・欠落・期限切れ・未承認を拒否する検証を維持した。
テストで作る新版の架空データは過去の実行結果ではない。

## 学び

契約ごとの版は異なるため、すべての schema_version を一括置換すると誤った形式になる。
参照元の JSON だけでなく、埋め込まれた schema と固定 digest の例も同時に揃える必要がある。
